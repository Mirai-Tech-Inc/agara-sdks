# TypeScript SDK design research

Research performed September 17, 2026, using official exchange repositories, official API documentation and published package metadata. This is design research, not a recommendation to inherit another exchange's wire formats, auth scheme, rounding rules or retry policy. Agara source commit a7e8c2dc1ab3b16f4133d0952347d5cc1bbd1b71 remains the contract authority.

## Specific implementation decisions

- Publish a focused ESM package with type declarations and `sideEffects: false`. Keep signing and streaming as explicit subpaths so simple REST consumers do not need a wallet framework or stream client initialization.
- Use native injectable fetch and AbortSignal. Maintain clear timeout/transport/decode/API failure classes, response headers and request IDs. Per-call deadlines must include response-body consumption and retry waits, not only request initiation.
- Separate public data access from PAT-authenticated account operations. Do not require fake tokens for anonymous reads. Missing local credentials should fail before network I/O for private methods.
- Generate concrete types from a checked-in scoped schema where useful, but reconcile omissions against actual mounted handlers and DTOs. Record the exact source commit and every source-driven schema supplement. Generation does not excuse `unknown` or generic object responses for known trader contracts.
- Preserve exact wire decimal strings and large identifiers. Use bigint for calculations/signing and explicit decimal-string conversion. Validate bounded quantities and reject unsupported precision. Do not route money through Number before signing. A lossless JSON parser must agree with declared TypeScript field types; silently converting an int64 field to bigint while its generated type stays number is unacceptable.
- Bind signed-order request economics to the signed envelope. One validated input builds the order hash, signature and POST body; callers should not repeat side/price/shares independently.
- Implement account-batch composition and hashing from Agara's actual domain and canonical ABI calls. Test both existing platform calldata/digest goldens. Different market routes must produce the correct target; unsupported routes must fail before signing. Deployment/domain inputs remain explicit rather than guessed.
- Treat accepted orders and accepted account batches as pending work. Use `is_terminal` for order completion and actual batch lifecycle states for batch completion. Preserve settlement/fill information separately.
- Retry only operations explicitly known to be safe reads, including read-only POST list routes where classified. Honor registered recovery instructions and Retry-After; do not replay ambiguous mutations or activate unknown recovery strategies. Surface oversized delays instead of sleeping less than the server requested.
- Expose complete envelopes and pagination primitives. Never turn partial exchange results into a complete empty portfolio. Iterators must keep filters stable, detect cursor cycles and honor cancellation; callers must be able to inspect raw page completeness and freshness.
- Model all six WebSocket subscription forms, including event_id. Event lifecycle notifications have no engine sequence. Handle every current account event, nested failures and provenance. Unknown frames remain inspectable, never silently converted into zero-valued known events.
- Keep stream queues bounded and signal discontinuity rather than silently dropping frames. Reconnect subscription transport with bounded jitter/backoff, but do not equate reconnection with reconstructed account state. Document current channel-specific REST reseeding and avoid invented replay guarantees.
- Parse SSE incrementally across UTF-8/chunk boundaries, handle comments and multiline data, support both current price endpoints, and release readers on cancellation. No Last-Event-ID replay promise exists unless the actual server supplies that contract.
- Test emitted requests and actual producer fixtures, not only method-name registration. Include package exports/imports, type-level constraints, cancellation, retry ambiguity, malformed/unknown frames, partial availability and lifecycle boundaries. Keep CI language-scoped so three branches can merge independently.

## Selected capability boundary

The common manifest includes 46 REST operations, two WebSocket endpoints and two SSE feeds: public/PAT trading, account batches, portfolio, bridge read/quote operations, LP rewards, realized PnL, core market/event/calendar/security/price discovery. It excludes home/navigation presentation, JWT browser account administration and separate withdrawal routes, operator/internal protocols, faucets, retired redemption HTTP routes, and unrealized PnL, which the platform does not support. A typed WITHDRAW operation inside an authorized PAT account batch is part of that batch contract; it is distinct from the excluded JWT withdrawal endpoint.

Source-driven scope correction: browser-config exposes only Privy signer_id/policy_ids, not local signer chain/contract configuration, and is excluded. Presigned batch helpers admit SPLIT/MERGE/WITHDRAW. REDEEM is retired by account_batch_gauntlet/ops_gate.rs and Across variants require PRIVY origin in account_batch_gauntlet.rs. Response schemas may preserve broader variants without advertising them as presigned trader actions.
